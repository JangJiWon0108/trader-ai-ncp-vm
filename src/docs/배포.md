# Trader-AI 배포 가이드 (백엔드 · 프론트엔드)

이 문서는 **레포 루트 = API**, **`frontend/` = 웹 UI** 기준으로 Docker 이미지 빌드와 Kubernetes 배포 절차를 정리합니다.

## 환경 구분

| 구분 | 설명 |
|------|------|
| **로컬 (macOS)** | 이미지 **빌드·푸시**는 [Colima](https://github.com/abiosoft/colima) 위의 `docker` CLI로 수행한다. 레지스트리는 **Docker Hub**, 네임스페이스(리포지토리 접두) **`jangjiwon`** (`jangjiwon/trader-ai`, `jangjiwon/trader-ai-web`). 개인 머신이라 범위가 한정된다. |
| **Kubernetes** | **공용 클러스터·공용 계정**을 쓴다. 다른 워크로드와 섞이지 않도록 **반드시 네임스페이스 `trader-ai-jjw` 안만** 사용한다(매니페스트·`kubectl -n` 일치). |

## 전제

- Colima 기동 후 `docker`, `kubectl`, Docker Hub 푸시 권한(`docker login`)
- 네임스페이스 `trader-ai-jjw` 사용(매니페스트에 고정). 없으면 생성:

```bash
kubectl create namespace trader-ai-jjw
```

- `k8s/deployment.yaml`·`frontend/k8s/deployment.yaml` 의 `image:` 는 아래와 같이 **Docker Hub `jangjiwon/...` 태그**와 맞춘다.
- API용 **ConfigMap·Secret**은 루트 `k8s/` 에 맞춰 준비합니다. 시크릿은 Git에 커밋하지 마세요.

## 아키텍처 요약

| 구분 | 경로 | Docker Hub 이미지 | K8s 리소스 |
|------|------|-------------------|------------|
| 백엔드 | 레포 루트 `Dockerfile` | `jangjiwon/trader-ai:latest` | `k8s/` — Deployment·Service 이름 `trader-ai` |
| 백엔드(ML 포함) | 레포 루트 `Dockerfile.ml` | `jangjiwon/trader-ai-ml:latest` | (선택) ML 의존성이 필요한 배포에서만 사용 |
| 프론트 | `frontend/Dockerfile` | `jangjiwon/trader-ai-web:latest` | `frontend/k8s/` — Deployment·Service 이름 `trader-ai-web` |

프론트 nginx는 **`/api/`** 요청을 클러스터 내부 **`http://trader-ai:8000/`** 로 넘깁니다(경로에서 `/api` 접두어 제거). 앱의 Vite 개발 프록시와 동일한 방식입니다.

배포 순서: **백엔드(Service `trader-ai` 가 먼저 떠 있어야)** 프론트의 `/api` 프록시가 동작합니다.

## 1. 백엔드 — Docker 빌드

레포 **루트**에서:

```bash
# (중요) K8s 노드(amd64)와 아키텍처를 맞춰 빌드 후 푸시
docker build --platform linux/amd64 -f Dockerfile -t jangjiwon/trader-ai:latest .
docker push jangjiwon/trader-ai:latest
```

- 컨텍스트는 루트 전체이며, 루트 `.dockerignore`로 `frontend/`·`k8s/` 등은 빌드에 포함되지 않습니다.
- 컨테이너는 `8000` 에서 Uvicorn으로 기동합니다.
- 빌드 시 `uv sync --frozen --no-dev` 로 **`[dependency-groups]` 의 `dev`(jupyter·matplotlib·nbconvert 등)** 는 이미지에 넣지 않습니다. 로컬에서 노트북까지 쓰려면 `uv sync` 또는 `uv sync --group dev` 로 설치한다.
- 빌드 과정에서 `uv` 다운로드 캐시가 이미지에 포함되지 않도록(이미지 용량 급증 방지) `uv` 캐시 디렉터리를 임시 경로로 사용 후 정리합니다.

### (선택) ML(추론) 의존성 포함 이미지 빌드

TensorFlow/Scikit-learn 등 무거운 의존성은 기본 API 이미지에서 분리되어 있습니다. 추론을 같은 컨테이너에서 수행해야 하면 아래 이미지를 사용합니다.

```bash
docker build --platform linux/amd64 -f Dockerfile.ml -t jangjiwon/trader-ai-ml:latest .
docker push jangjiwon/trader-ai-ml:latest
```

## 2. 백엔드 — Kubernetes

`k8s/deployment.yaml` 의 `image: jangjiwon/trader-ai:latest` 가 푸시한 태그와 일치하는지 확인한 뒤:

```bash
kubectl apply -f k8s/configmap.yaml
kubectl apply -f k8s/secret.yaml
kubectl apply -f k8s/deployment.yaml
kubectl apply -f k8s/service.yaml
kubectl apply -f k8s/pdb.yaml
```

`k8s/pdb.yaml` 은 **PodDisruptionBudget**으로 노드 드레인 등 자발적 중단 시에도 가용 Pod를 최소 1개 유지하려는 설정입니다.

상태 확인:

```bash
kubectl -n trader-ai-jjw rollout status deployment/trader-ai
kubectl -n trader-ai-jjw get pods,svc -l app=trader-ai
```

---

## 3. 프론트엔드 — Docker 빌드

**`frontend/` 디렉터리**를 빌드 컨텍스트로 사용합니다.

```bash
# (중요) K8s 노드(amd64)와 아키텍처를 맞춰 빌드 후 푸시
docker build --platform linux/amd64 -f frontend/Dockerfile -t jangjiwon/trader-ai-web:latest frontend
docker push jangjiwon/trader-ai-web:latest
```

- `frontend/.dockerignore` 로 `node_modules`·`dist`·`k8s/` 등이 제외됩니다.
- 이미지 안의 nginx는 **80** 포트에서 정적 파일을 제공하고 `/api/` 를 API로 넘깁니다.

---

## 4. 프론트엔드 — Kubernetes

`frontend/k8s/deployment.yaml` 의 `image: jangjiwon/trader-ai-web:latest` 가 푸시한 태그와 일치하는지 확인한 뒤:

```bash
kubectl apply -f frontend/k8s/deployment.yaml
kubectl apply -f frontend/k8s/service.yaml
kubectl apply -f frontend/k8s/pdb.yaml
```

확인:

```bash
kubectl -n trader-ai-jjw rollout status deployment/trader-ai-web
kubectl -n trader-ai-jjw get pods,svc -l app=trader-ai-web
```

외부 노출 주소(LoadBalancer 또는 Ingress에 따름):

```bash
kubectl -n trader-ai-jjw get svc trader-ai-web
```
