# 개발표준 (가독성 · 주석 · 리팩터링 기준)

`trader-ai` 코드의 **일관성**, **초보자도 따라가기 쉬운 구조**, **리팩터링 시 AI·인간이 동일한 기대를 갖도록** 하는 가이드라인이다.  
“초보자도 이해하기 쉽다”는 **한 줄에 여러 단계를 몰아 넣지 않고**, **의미 단위로 나누고**, **이름으로 의도를 드러내는 것**을 뜻한다(아래 **3. 코드 가독성 원칙** 첫 항목).  
도메인별 파일 배치·프레임워크 세부는 별도 문서로 두고, 여기서는 **임포트·접근 규칙**, **독스트링·주석**, **가독성**만 다룬다.

---

## 1. 임포트 및 심볼 노출 규칙

### 1.1 임포트 순서

1. `from __future__ import ...` (사용하는 경우만, 파일 최상단)
2. 표준 라이브러리
3. 서드파티
4. 로컬 모듈 (가능하면 프로젝트 루트 기준 절대 경로 스타일로 통일)

각 그룹 사이에 빈 한 줄을 둔다.

### 1.2 접근 제한 (Python)

| 구분 | 규칙 |
|------|------|
| 공개 API | 접두사 없음. 모듈·패키지 외부에서 호출·임포트해도 되는 심볼 |
| 내부 전용 | 함수·메서드·변수는 선행 `_` (해당 모듈 내부에서만 사용) |
| 모듈 상수 | `_UPPER_SNAKE_CASE` (모듈 내부 상수), 공개 상수는 팀 합의에 따름 |

## 2. 주석 및 독스트링 (Docstring)

### 2.1 파일·모듈 (Python)

- 모든 `.py` 파일 최상단에 **한글 모듈 독스트링**을 둔다.
- 내용: 이 파일의 **역할**, **다른 모듈과의 경계**, **핵심 흐름**을 2~6문장 정도로 요약한다.

### 2.2 함수·클래스 (Google 스타일)

- **공개 함수·클래스**, **HTTP·외부 API·큐·스케줄러 등 경계**에 있는 함수: `Args`, `Returns`, 필요 시 `Raises`를 작성한다. (제너레이터만 `Yields` 사용)
- **단순 내부 헬퍼**이고 이름만으로 의미가 분명하면 **한 줄 독스트링**으로 충분하다.
- **요청 스코프·세션·캐시 등 공유 저장소를 바꾸는 함수**: 독스트링에 **무엇이 어디에 어떤 키·속성으로 반영되는지**를 명시한다. (예: FastAPI `request.state`, 세션 dict, Redis 키)

```python
def sync_user_context(user_id: str) -> None:
    """
    외부 인증 응답을 앱 컨텍스트에 반영한다.

    Args:
        user_id: 동기화 대상 사용자 식별자.

    컨텍스트에 반영되는 값:
        - current_user_id: 이후 핸들러에서 읽는 활성 사용자 id
    """
```

### 2.3 논리 블록 구분·인라인 주석

- 연관된 코드 뭉치(임포트, 설정, 헬퍼, 본 실행부 등)는 **시각적 구분선**으로 나눈다.

  ```text
  # ─── 모듈 임포트 ───
  # ─── 설정 로드 ───
  # ─── 상수 정의 ───
  # ─── 헬퍼 함수 ───
  # ─── 공개 API ───
  ```

- **같은 종류의 파일끼리는 섹션 제목을 통일**한다. 파일마다 `# 임포트`, `# 설정 및 상수`, `# 기타`처럼 제각각 쓰지 않는다.
- **모듈 유형별 권장 섹션 템플릿** (필요한 것만 사용, 순서는 유지):

  | 모듈 유형 | 섹션 (위에서부터) |
  |-----------|-------------------|
  | 서비스·도메인 로직 (`app/services/` 등) | 모듈 임포트 → 설정 로드 → 상수 정의 → 헬퍼 함수 → 공개 함수·클래스 |
  | API 라우트 (`app/api/routes/` 등) | 모듈 임포트 → 라우터·스키마 → 엔드포인트 핸들러 |
  | Pydantic·DTO 스키마 | 모듈 임포트 → 스키마 정의 |
  | 미들웨어·백그라운드 작업 | 모듈 임포트 → 상수 정의 → 헬퍼 함수 → 핸들러 본체 |

- 복잡한 로직에는 **단계 주석**을 허용한다. 예: `# 1단계: 입력 검증`, `# 2단계: 외부 호출`.
- 주요 모듈 수준 변수 위에는 **목적**을 한 줄로 적는다.

### 2.4 한글 단일행 주석 (`# ...`) 문체

- **서술어 어미**(`~한다`, `~합니다`, `~됩니다`, `~있습니다`)보다 **명사형·명사구**로 끝낸다.
  - 좋은 예: `외부 API 오류 시 재시도`, `캐시 미스 조건`, `로깅용 스냅샷`
  - 피할 예: `외부 API 오류 시 재시도합니다`
- 예외: 구분선(`# ─── … ───`), 영문만 있는 주석, 인라인 끝 주석(`x = 1  # noqa` 등).

## 3. 코드 가독성 원칙

- **의도가 한눈에 보이게 나눈다.** 여러 단계를 한 줄·한 표현식에 압축하지 않는다. 단계마다 **의미 있는 이름의 변수**에 담거나, **짧은 블록·작은 함수**로 쪼개 위에서 아래로 읽으며 흐름을 따라갈 수 있게 한다. “짧은 코드”보다 **처음 보는 사람도 의도를 추적할 수 있는 코드**를 우선한다.
- 주석은 **이 블록이 무엇을 하는지**(흐름·단계·도메인 의미)를 읽는 사람이 바로 따라갈 수 있게 돕는다. 특히 분기·중첩·외부 규격이 섞인 구간에는 **무엇**을 명시하는 것이 중요하다. 여기에 더해 **배경**, **제약**, **예외 처리 이유**, **버그 회피 이유**처럼 코드만으로는 드러나기 어려운 **왜**도 남긴다.
- **이름**(상수·함수·변수)과 짧은 코드로 이미 분명한 한 줄짜리 동작에, 같은 말을 반복하는 주석만 달지 않는다.
- **헬퍼**는 중복 제거, 외부 경계 정리, 복잡도 분리에 **실제 이득**이 있을 때만 만든다.
- **긴 문자열**(SQL 템플릿, 고정 안내 문구, 긴 포맷 문자열)은 `QUERY_TEMPLATE`, `USER_MESSAGE_*` 같은 **모듈 상수**로 분리해 본문 로직을 읽기 쉽게 한다.
- **외부 연동**은 책임을 나눈다: 연결·설정 → 요청 구성 → 응답 파싱·변환.
- **오류·실패**: `print` / `traceback.print_exc()`만으로 끝내지 않고 **logger**를 사용한다. 사용자에게 보여 줄 메시지는 **한곳에서 조립**하거나 헬퍼로 모은다.
- **독스트링**: 표준 맞추기용 장문은 피한다. 짧은 함수는 **한 문장**으로 충분하고, **공개 경계**만 `Args` / `Returns`를 상세히 쓴다.

## 4. 리팩터링·코드 리뷰 시 체크리스트

- [ ] 새 파일에 모듈 독스트링(한글)이 있는가.
- [ ] 공개·경계 함수에 인자·반환(·부수 효과) 설명이 있는가.
- [ ] 섹션 구분선과 섹션 이름이 **같은 유형 파일**과 일치하는가.
- [ ] 한글 `#` 주석이 명사형으로 통일되어 있는가.
- [ ] 임포트 순서·그룹 간 빈 줄이 지켜졌는가.
- [ ] 가독성 원칙(의도 분해·한 줄 과밀도 회피, 긴 문자열 분리, logger, 외부 연동 분리)을 위반하지 않았는가.

이 문서는 필요 시 팀 합의로 수정하되, **주석 스타일·섹션 이름·경계 독스트링**은 자주 바꾸지 않는 것이 리팩터링 비용을 줄인다.
